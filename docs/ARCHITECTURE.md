# Subway Domino — Architecture Contract (v1)

This is the binding engineering contract for building Subway Domino (spec of record: `PRD.md` v1.1).
Sections marked **CONTRACT** are interfaces other components depend on: implement them exactly, or change them only by editing this file and every consumer in the same change. Sections marked **GUIDANCE** recommend an approach. The owner may improve on it, as long as every CONTRACT and every listed test still holds.

## 2. Data pipeline (WP1)

### 2.1 Sources & fetching — CONTRACT

`build_nyc_network.py` steps:
1. **GTFS.** Read the `fgm6-ccue` view metadata (`https://data.ny.gov/api/views/fgm6-ccue.json`) and collect every URL containing `nyct/subway`. Try each, accepting a response only if it is a zip containing `stops.txt`, `stop_times.txt`, `trips.txt`, `routes.txt` and `shapes.txt`. Fall back to `https://rrgtfsfeeds.s3.amazonaws.com/gtfs_subway.zip`, then to the cached `data/raw/gtfs_subway.zip`. Cache the result under `data/raw/`.
2. **Complexes.** Fetch `https://data.ny.gov/resource/5f5g-n3cz.json?$limit=5000` (all rows) and cache the JSON.
3. **Ridership.** Run a single SoQL aggregation against `https://data.ny.gov/resource/5wq4-mkjj.json`:
   - `$select=station_complex_id, date_extract_hh(transit_timestamp) AS hh, sum(ridership) AS r, count(distinct date_trunc_ymd(transit_timestamp)) AS days`
   - `$where=transit_timestamp >= '<max_ts − 56 days>' AND date_extract_dow(transit_timestamp) BETWEEN 1 AND 5`
   - `$group=station_complex_id, hh`
   - `$limit=50000`

   Get `max_ts` from a cheap `$select=max(transit_timestamp)` query. Average entries per hour = `r / days`. If `count(distinct …)` isn't supported, use a separate distinct-day query. Cache the JSON.
4. **Basemap.** Fetch NYC borough boundaries (NYC Open Data `gthc-hcne` GeoJSON export). Simplify with Douglas–Peucker (ε = 25 m) and drop Staten Island. On failure, emit no basemap (the frontend handles that).

All HTTP goes through `urllib.request` with a generic User-Agent `subway-domino-build/1.0`, a 120 s timeout and 3 retries with backoff. Send no personal data.

**Deterministic fallbacks.** Record each one in `build_manifest.json.fallbacks_used`:
- **Complexes unreachable:** derive complexes from GTFS parent stations, unioned via `transfers.txt` pairs whose `from` ≠ `to`. The complex id becomes `G<parent_id>`.
- **Ridership unreachable:** synthesize `entries[c,hh] = base(c) · hourly_curve(hh)`.
  - `base = 900 · n_routes(c)^1.3 · (2.5 if cbd else 1) · borough_factor` (M 1.4, Bk 1.0, Q 1.0, Bx 0.8).
  - `hourly_curve` is the fixed 24-value system curve measured on 2026-11-19: `[26397,10364,6662,7803,20671,68580,156526,323245,398287,258058,176133,162998,173459,195961,243161,304758,348614,421687,323072,208894,153213,125857,101315,64142]`, normalized to sum to 1.
- **Basemap unreachable:** no basemap.
- `--offline`: no network access. Use `data/raw/` caches if present. Otherwise, if committed artifacts exist, validate them and exit 0.

The build must be **deterministic**: same inputs give a byte-identical output. Sort everything, round floats (coordinates 0.1 m, rates 1e-4), and use no timestamps except in `build_manifest.json`.

### 2.2 Scope

Keep only routes in §0 (drop `SI`) and parent stations used by in-scope patterns. Use only `service_id == "Weekday"` trips for service and run-time statistics. Trips starting at or after 24:00 are dropped from the cyclic day.

### 2.3 Topology inference — GUIDANCE (outputs are CONTRACT in §2.6)

1. **Patterns.** A pattern is a `(route, ordered parent-station sequence)` taken from weekday trips. Keep a pattern only if it has ≥ 3 trips per weekday, or it is the only pattern for its route and direction.
2. **Elementary hops.** Directed station pairs `(u,v)` consecutive in some pattern. A hop that bypasses stations is decomposed into the chain of elementary hops of a pattern that stops at the intermediate stations between `u` and `v` (choose the chain with the most trips). Where no such chain exists, the hop is itself elementary.
3. **Physical direction & track nodes ("through-route components").** At each station, union-find the occurrences `(station, incoming elementary hop)` and `(station, outgoing elementary hop)` of every pattern pass. Two passes share a node if they share an incoming or an outgoing hop **on the same track class**. Never use `direction_id` or the N/S suffix (§0).
4. **Express tracks.** A directed elementary hop gets an **X** (express) track in addition to **L** (local) when there is overtake evidence: some trip departs `u` after another trip and reaches `v` first, and their stop patterns differ inside the run. Use weekday trips with a minimum of 3 overtakes. All stations along a maximal X run get an X node: with a platform where an express pattern stops, without one where expresses pass. Skip-stop (J/Z) has 0 overtakes, so it stays a single track. 3-track lines get X edges in both directions, sharing a `bidir_group` id. `infrastructure.json` adds known middle tracks that have no express service in this pick (Jerome 4, West End D) and declares each 3-track group's peak direction.
5. **Crossovers (interlockings).** Add `crossover` edges `L→X` and `X→L` (same direction, same station) where a pattern changes track class at a station. Also apply **standard placement**: every station that has both an L and an X node with platforms (an express station on a 3/4-track trunk) gets crossovers in both senses in both directions. Each crossover takes `CROSSOVER_S = 20` s.
6. **Turnbacks.** Add `turnback` edges from a node to the opposite-direction node of the same station, same route set, at:
   - (a) the terminals of every pattern (normal terminal relay);
   - (b) **turnback-evidence stations**: non-terminal stations where some weekday pattern of the route starts or ends (≈44);
   - (c) stations listed in `infrastructure.json.turnbacks`.

   A turnback edge carries `pocket: true` when it is a center/pocket track that doesn't block through tracks (the default for (b) and (c)), and `pocket: false` at terminals.
7. **Divisions.** Every node and edge inherits the division of its station. **No edge may connect nodes of different divisions** (asserted).
8. **CBTC.** `infrastructure.json.cbtc` lists corridors as `{route ids, from_gtfs, to_gtfs}`. Edges on those station ranges get `cbtc: true`: the whole L and 7/7X, Queens Blvd 50 St/Queens Plaza→Kew Gardens-Union Tpke (E/F/M/R), and 8 Av 59 St-Columbus Circle→High St (A/C/E).
9. **Yards.** These come from `infrastructure.json.yards`: the 10 PRD yards (207 St, Concourse, Coney Island, Jamaica, Pitkin, Livonia, Corona, Canarsie, 239 St, Pelham). Each entry has `division`, lat/lon, the lead station(s) (GTFS ids), `routes`, `fleet_cap` (4–8) and `deadhead_s` (300–720). Emit a yard node per yard and `yard_lead` edges to the matching nodes, in both directions where the routes run.
10. **Geometry.** Cut each segment's polyline from the shapes of a pattern that traverses it, between the projected station points. Simplify with Douglas–Peucker ε = 2 m. Project with the local equirectangular projection in §2.6.
11. **Run times.** `run_s` for each running edge is the median over weekday trips of the scheduled hop time attributable to the edge. Express hops spanning several X edges are split by edge length. Stopping hops get an extra 25 s removed as a nominal dwell (floor 30 s). `v_max = clamp(length_m / max(run_s − ACCEL_DECEL_LOSS_S, 20), 8, 24.6)` m/s.
12. **Platforms & capacity.** A platform is a `(station, physical direction)` group of nodes that share boarding. An island platform serving L and X in the same direction is one platform; L and X nodes at a local station in the same direction map to one platform. Capacity in riders: `clamp(350 + 0.30 · peak_hour_entries_on_platform, 350, 3500)`.
13. **Demand.** Profiles and windows: `am_peak` 07–10, `midday` 10–16, `pm_rush` 16–19, `late_night` 00–05. A complex's entries/h is the mean over the window's hours. They are split over the complex's platforms in proportion to weekday trains/hour serving each platform in that window. Attraction per station per profile uses the mirror-hour rule (am_peak attraction ∝ pm_rush entries, pm_rush ∝ am_peak, midday and late_night ∝ same-window entries), normalized to sum to 1.
14. **Service.** For each profile and pattern: `headway_s` = window length ÷ weekday departures in the window (omit the pattern if it has none), and `phase_s` = the first departure offset in the window mod `headway_s`.

### 2.5 Hubs

A station is a **hub** if its complex is in the top 40 by weekday entries, OR its complex serves ≥ 4 routes, OR it is in `hubs_extra`. Hubs matter for the SKIP_STOP mask.

**Invariants**, asserted by `tests/test_network_artifacts.py` and by `build --check`:
- every pattern's edges are consecutive (`edges[i].to == edges[i+1].from`);
- every `stops==1` position lands on a node with `platform ≥ 0`;
- no cross-division edge;
- every in-scope station has ≥ 1 node, and every node has an in-edge or an out-edge;
- every route has ≥ 1 pattern with service in `am_peak`, except routes with no weekday AM service in the feed (record them);
- 424 complexes, 475 stations, 28 routes;
- nodes within 1,100–1,700; run edges within 1,100–1,800; segments within 400–560;

### 3.3 Trains & movement — GUIDANCE (behavior is CONTRACT via tests)

- **State is struct-of-arrays over `MAX_TRAINS` slots.** Fields include `active`, `route`, `pattern`, a per-train **path** (int32 `[MAX_TRAINS, MAX_PATH=96]` of edge ids with `stop` flags), `ptr` (index into the path), `offset_m`, `v`, `dwell_left`, `hold_total`, `onboard[MAX_TRAINS, N_DEST]`, status bits, `last_depart_s` and `lateness_s`. Path rewrites happen only on actions and terminal relays; they are rare and may be Python-side. The per-tick kinematics are vectorized.
- **Movement authority** comes from one braking-curve kernel. It finds the distance to the nearest obstacle along the train's path: the leader's rear, a red signal at a disrupted edge's entry, a closed node, a stop point, or a merge conflict. In **fixed-block** mode the authority ends at the start of the block containing the obstacle (block boundaries every `BLOCK_M` along each edge), minus 10 m. On **CBTC** edges it ends at `obstacle − CBTC_MARGIN_M`. Speed is `min(v + ACCEL·dt, v_max_edge, sqrt(2·BRAKE·authority))`. The train may not pass the authority end within the tick. Look ahead up to 3 edges along the path.
- **Merges.** When several trains would enter the same edge in a tick, only the earliest-arriving one enters. Ties go to the lowest scheduled departure, then the lowest slot. The others stop at the edge entry.
- **Stations.** On reaching a stop node, a train dwells for `dwell` (§3.2), with boarding and alighting during the dwell. At the end of the dwell it becomes **ready to depart**. If any non-CONTINUE action is valid for it, a decision is requested (§4.1). Otherwise it departs once authority > 0.
- **Timetable.** Each `(profile, pattern)` departs from its origin every `headway_s` (with `phase_s`). A departure takes a train from the origin terminal's pool. Trains arriving at a terminal join the pool after `LAYOVER_S`, are re-assigned to one of `next_patterns`, and the pool is shared by route at that station. At reset, place trains along every pattern at the positions implied by departures in the last cycle, and seed each terminal pool with `ceil(LAYOVER_S / headway) + 1` trains. A missing train means a missed departure (a service gap): that is the cascading effect.
- **Normal Schedule:** every decision resolves as CONTINUE. There is no other control logic. Trains dwell, depart when authority allows, and queue at red signals.
- **3-track peak direction.** X edges in a `bidir_group` are usable only in the profile's allowed direction (`peak_dir`). Other X usage is masked.

### 3.4 Passengers — GUIDANCE

- **Fluid riders.** Each platform has `waiting[n_platforms, N_AGE_BINS]` (float32). Each tick adds `platform_rate · demand_scale · DT_S` to bin 0 and shifts bins every 60 s. Closed platforms take no arrivals; riders at a platform that closes are moved to `displaced`, and the closure is counted in its cost.
- **Boarding** at a stop, oldest bins first: `min(waiting, capacity − onboard − alighting)`. Boarders are spread over the next `N_DEST` stops of the train's **actual** path, weighted by `attraction[station] · decay(k)` with `decay(k) = exp(−k/8)`, normalized. Riders destined beyond the 12th stop go into the last bucket.
- **Alighting.** Bucket 0 alights at a stop (counted in `riders_served`), and the remaining buckets shift down by one. Some alighters transfer:
  - fraction: `TRANSFER_FRAC = 0.25` at stations whose complex has ≥ 2 stations, or ≥ 3 routes;
  - destination: they join other platforms of the same complex, weighted by platform rate.
- **Spillover.** At a complex with ≥ 2 platforms, riders waiting more than 12 min at a platform whose next train is more than `3 × sched_headway` away move to other platforms of the complex at 5 %/min.
- **SKIP_STOP:** bucket 0 merges into bucket 1 (overshoot) and counts toward the skip displacement cost.
- **Short-turn:** all onboard riders are moved to the turnback station's opposite-direction-agnostic platform in the original direction (they wait for the next train), and the short-turn displacement cost applies.

### 3.5 Disruptions — CONTRACT semantics

| kind | allowed targets | effect while active |
|---|---|---|
| `local_block` | segment, station, interlocking | Every **L** running edge of the segment, both directions, is blocked (authority stops at its entry). For a station or interlocking target, L edges entering and leaving the station's L nodes are blocked |
| `express_block` | segment (must have express), station or interlocking with X nodes | The same for **X** edges. `ValueError` if the target has no X track |
| `full_station_closure` | station, complex | All nodes of the station(s) are closed: no train may enter, platforms are closed to passengers, and waiting riders are displaced. Trains already inside stay, doors closed (counted as held, not tunnel) |
| `signal_delay` | segment, interlocking | Affected edges (all tracks of the segment, or all edges touching the interlocking's station) get `v_max = 4.5 m/s` and **single-train occupancy** (the whole edge is one block). Each train entering pays a 45 s key-by stop at the entry. Crossovers at an affected interlocking are unusable |

- `duration_s = None` means the disruption lasts until it is cleared. Training scenarios sample 600–2400 s. When a disruption ends, its effects are lifted in the same tick.
- Disruption ids increase monotonically per session.
- Labels are plain English, e.g. "Station closed: 14 St-Union Sq", "Local track blocked: 59 St ↔ 51 St", "Signal problems at Times Sq-42 St".

### 3.6 Determinism

Given the same `Scenario`, the same `apply_actions` calls at the same ticks give an identical `state_hash()`. The demand is fluid and deterministic. Randomness (turnback latency draw, domain randomization) comes only from the scenario seed's generator, and the order of draws is fixed.

## 4. RL formulation (shared NumPy parts in `sim/`, Gym/SB3 in `rl/`)

### 4.1 Decision events — CONTRACT

- A decision fires for a train when it is **ready to depart** a stop (dwell done, or a hold step expired) **and** ≥ 1 non-CONTINUE action is valid.
- All decisions of one tick are computed from **one snapshot**, as one `DecisionBatch` holding obs and masks for all of them.
- The server applies them in batch order. The Gym env serializes the batch, one ego per `env.step()`, and applies each action immediately via `apply_actions` (re-validated) **without recomputing obs**. Training and serving therefore share identical semantics.
- When the batch is exhausted, the env advances the sim tick by tick until the next non-empty batch or the episode's end.

### 4.2 Actions & masks — CONTRACT (`sim` computes masks; same code path in training and serving)

**Definitions**
- `leader_gap_s` is the headway to the train ahead at its location: the nominal time-to-reach its front along the path (timetable run profile including dwells), plus its elapsed platform dwell (capped at 45 s). A red signal at a disruption ahead counts as a stuck leader. A stuck leader just ahead therefore gives a small gap. `follower_gap_s` is defined symmetrically.
- `sched_h` is the **combined** scheduled headway of all patterns on the track where the gap is measured. On a shared trunk the leader is usually another route.
- `ref_h` (to a given neighbour) is `min(sched_h, planned)`, where `planned = gap − (late_behind − late_ahead)` is the gap the timetable itself intends between the two trains. Short-gap clauses ("bunched", "follower gap <") compare against `ref_h`. On shared trunks, patterns with different headways merge unevenly by timetable, so judging them against `sched_h` alone fires on calm service. "Headway not already wide" keeps `sched_h`. (`MASK_REVISION = 2`; it took calm am_peak from 7,541 to 865 decisions per sim-hour.)
- `blocked_ahead` is true if, within the next `K_AHEAD` stations of the path, any edge or node is blocked or closed by a disruption, OR ≥ 2 trains are stopped outside platforms.
- `hub` is defined in §2.5. A *critical wait* at a platform means the mean wait is ≥ 10 min, or the oldest non-empty bin is ≥ 20 min.

| id | name | valid iff (all clauses) | effect |
|---|---|---|---|
| 0 | `CONTINUE_SCHEDULED` | always | depart per schedule/authority |
| 1 | `HOLD_IN_STATION` | at a platform ∧ `hold_total < MAX_HOLD_S` ∧ `leader_gap_s < 1.5·sched_h` (headway not already wide) ∧ (`leader_gap_s < 0.75·ref_h` ∨ `blocked_ahead`) | stay `HOLD_STEP_S` with doors open (boarding continues); the decision recurs after |
| 2 | `RUN_EXPRESS` | on an L node with an L2X crossover usable by this train ∧ an express alternate exists (rejoins the train's path) ∧ the alternate's X edges are open (incl. peak direction) ∧ the train's own L path to the rejoin point is `blocked_ahead`-affected (disrupted or ≥ 2 stopped trains) | switch to the X track until the rejoin; bypassed L stops are skipped (skip displacement for each) |
| 3 | `RUN_LOCAL` | mirror of 2: on an X node with an X2L crossover ∧ a local alternate exists ∧ the L edges are open ∧ the train's X path to the rejoin is disrupted or congested | switch to L, stopping at every L platform until the rejoin |
| 4 | `SKIP_STOP` | next scheduled stop exists ∧ is not a terminal ∧ is not a hub ∧ the train did not skip its previous stop ∧ (the next stop has no critical wait ∨ it is closed) ∧ (`lateness_s > 120` ∨ the follower gap < 0.5·`ref_h`) | pass the next stop without stopping |
| 5 | `SHORT_TURN_RELAY` | the current station has a **pocket** turnback edge usable by this route ∧ it is not a terminal of the pattern ∧ the pocket is free ∧ (the train would reach the first blocked edge or closed station on its path to the terminal within `SHORT_TURN_BLOCK_HORIZON_S` = 900 s of nominal running ∨ the opposite direction's gap at this station > 2·`sched_h` while the follower gap < 0.5·`ref_h`) | discharge all riders, traverse the turnback (`TURNBACK_S` ~ U[180,300] s), continue as the reverse pattern of the same route from here |
| 6 | `REROUTE_VIA_COMPATIBLE_TRUNK` | the train is at a diverge junction where a same-division alternate path (precomputed by `graph.py`: shortest path by run time via a different out-edge, rejoining the pattern within 30 stations with ≤ 2.5× the original time, or reaching a terminal served by the route) exists ∧ the alternate is open ∧ the original path to the rejoin point is blocked | follow the alternate path; onboard riders whose destinations are bypassed count toward the reroute cost |
| 7 | `DISPATCH_YARD_GAP_TRAIN` | a yard compatible with the route (same division, `routes` ∋ route) has stock > 0 ∧ yard cooldown is inactive ∧ a downstream segment is starved (the yard's lead node is on the train's remaining path or the route's pattern, and the expected time until the next in-service train on the lead's track (any pattern using the edge leaving the lead node) reaches it > max(2·`sched_h`, 480 s)) | after `deadhead_s`, a gap train enters at the lead node and runs the train's pattern from there; stock −1, cooldown starts |

Masks are never "need-free" for actions 1–7. The need clauses above are part of the physical/operational masking contract and documented in the info modal. They keep calm service nearly decision-free. The policy, not hand-written logic, chooses among valid actions, CONTINUE included.

### 4.3 Observation — CONTRACT dimension, GUIDANCE layout (`sim` exports `OBS_DIM`, `FEATURE_NAMES`)

`OBS_DIM = 216` = 10 corridor slots × 18 + 28 ego features + 8 mask bits. All values are clipped to [−1, 1].
- **Slots** are the train path's stations: slots 0–2 are the 3 stations behind (most recent last), slot 3 is the current station, and slots 4–9 are the next 6 stations. Each slot's 18 features:
  - `valid`, `is_stop`, `has_platform`, `is_hub`, `is_terminal`
  - `waiting/1000` (log-scaled), `mean_wait/15`, `crowd_ratio`
  - `edge_blocked` (the next edge on the path), `edge_signal_delay`, `node_closed`
  - `trains_stopped_on_next_edge/3`, `time_since_last_departure/(2·sched_h)`
  - `has_L2X/X2L`, `has_pocket_turnback`, `is_diverge`, `cumulative_run_time_from_ego/1800`
  - `onboard_bucket_share` (share of the ego's riders alighting there)
- **Ego (28):**
  - `load`, `leader_gap/sched_h`, `follower_gap/sched_h`, `lateness/600`, `hold_total/MAX_HOLD_S`
  - `skipped_prev`, `on_X`, `cbtc`, `division`, profile one-hot (4)
  - `route_avg_wait/15`, `route_tunnel_stuck/5`, `n_active_disruptions/4`, `min_disruption_dist_slots/6`
  - `yard_stock_frac`, `yard_cooldown_frac`, `opposite_dir_gap/(2·sched_h)`, `is_gap_train`, `is_deviated`
  - `sched_h/900`, `time_in_episode_frac`, `demand_scale−1`, 3 reserved zeros
- **Mask bits:** the row of `masks` as 0/1.

`build_obs` is pure NumPy, vectorized over the batch, and is the **only** observation code (env and server both call it via `pending_decisions()`).

### 4.4 Reward — CONTRACT (implements PRD §4.3)

Per-tick cost of a sim (`sim` computes it in `cost_totals()` increments; Δt = `DT_S/60` minutes):
```
C_wait   = W_WAIT  · Σ_p Σ_b waiting[p,b] · age_b^1.5 · Δt            age_b = b + 0.5 min (last bin 30)
C_tunnel = Σ_trains tunnel_stopped · (W_TUNNEL_TRAIN + W_TUNNEL_RIDER · onboard · a^TUNNEL_RIDER_AGE_EXPONENT) · Δt
           (stopped outside platform, v<0.5, any duration; a = minutes stopped, clipped to [1, 30]; exponent 1.5,
            so a rider trapped 30 min weighs like one waiting 30 min on a platform; 0.0 restores the original flat term)
C_hold   = Σ_trains held_by_action  · (W_HOLD_TRAIN   + W_HOLD_RIDER   · onboard) · Δt
C_crowd  = W_CROWD · Σ_p (max(0, waiting_p/cap_p − 0.8) / 0.2)^2 · Δt
Immediate (at action time): short_turn = W_ST · riders_forced_off; skip = W_SKIP · riders_overshot; reroute = W_REROUTE + W_REROUTE_RIDER · riders_displaced; yard = W_YARD
```
| Coefficient | Value |
|---|---|
| `W_WAIT` | 1.0 |
| `W_TUNNEL_TRAIN` | 200 |
| `W_TUNNEL_RIDER` | 1.0 |
| `W_HOLD_TRAIN` | 10 |
| `W_HOLD_RIDER` | 0.05 (tunnel ≫ hold; WP5c tried 0.5: fewer holds but no wait gain, so reverted) |
| `W_CROWD` | 500 |
| `W_ST` | 10 |
| `W_SKIP` | 5 |
| `W_REROUTE` | 300 |
| `W_REROUTE_RIDER` | 2 |
| `W_YARD` | 400 |
| `REWARD_SCALE` | 1/2000 |
| `REWARD_CLIP` | 100 (was 10: that clipped 13 % of Stage 1 steps and 27 % in meltdowns; 100 clips ~0.2 %) |

The RL owner may recalibrate these values. Any change is made only in `constants.py` and documented in the model card.

**Counterfactual-twin difference reward (credit assignment).** The env runs the AI sim and a **Normal twin** reset from the same `Scenario`. The twin advances in lockstep and resolves all its decisions as CONTINUE.
- The reward for `env.step()` is `clip(−REWARD_SCALE · (ΔC_ai − ΔC_twin + immediate_cost_of_this_action), ±REWARD_CLIP)`. ΔC is the cost accumulated over the ticks advanced inside this step. That is zero when the next decision is in the same tick.
- The twin is action-independent, so this is an unbiased variance-reduced signal.
- With deterministic fluid demand, regions untouched by AI actions contribute exactly 0. Credit concentrates where actions mattered, and the return is exactly "how much better than Normal Schedule", which is the product's claim.

**Training credit: per-train semi-MDP (WP5b, `rl/credit.py`; the training default).** The env reward above is unchanged, and so are the env checkers, plain MaskablePPO and evaluation. The trainer builds its own per-train reward from the same twin difference, split by where the cost arose:
- With `track_cost_vectors` set (the env sets it), each sim also accumulates `cost_vectors()`: wait + crowd per platform and tunnel + hold per route's trains (`sim/cost.py tick_cost_vectors`, in the same tick code as `cost_totals()`; their sums equal the scalar terms within 1e-9 relative). Immediate action costs stay with the acting train.
- Scope of an ego on route r (`scope_weights`): a platform weighs 1 if r serves it, `NEIGHBOR_W` (0.35, `--scope-neighbor-weight`) if a route that shares a run edge with r serves it, else 0; trains of r weigh 1, those of track-sharing routes `NEIGHBOR_W`, others 0. `d_route[r] = W_plat[r]·(Δplat_ai − Δplat_twin) + W_rt[r]·(Δrt_ai − Δrt_twin)` per step.
- Train i decides at step k (episode time t_k) and next decides at k′ (or the episode ends):
  ```
  R_k     = −REWARD_SCALE · (imm_k + Σ_{m=k}^{k′−1} γ_min^((t_mid(m) − t_k)/60) · d_route_m[r_i])     t_mid(m) = t_m + ticks_m·DT_S/2
  Γ_k     = γ_min^((t_k′ − t_k)/60)          γ_min = 0.96 per sim-minute (17-min half-life), --gamma-min
  δ_k     = R_k + Γ_k·V(o_k′) − V(o_k)       the episode horizon is terminal (no bootstrap)
  A_k     = δ_k + Γ_k·λ·A_k′                 λ = 0.95 per own decision; returns A + V
  ```
- `--reward-scope global` uses the citywide `d_flow_global` instead of `d_route` (ablation). Under all-CONTINUE play every `d_route`, `d_flow_global` and R is exactly 0 (tests, all three twin modes).
- `--credit serial` is the WP5 baseline, kept as an ablation and bit-identical to it: one GAE chain per worker over the interleaved decisions, γ = 0.995 per decision, the env's citywide reward.

### 4.5 Gym env — CONTRACT (`rl/env.py`)

`SubwayDominoEnv(gymnasium.Env)`:
- `__init__(stage: int = 2, seed: int | None = None, graph_path: str | None = None, scenario_fn=None, *, twin_mode: str = "lazy", credit_info: bool = True, scope_neighbor_weight: float = 0.35, calm_frac: float = 0.0)`. Twin modes: `lazy` forks `sim.copy()` just before the first non-CONTINUE action; `copy` and `reset` are alternatives. Tests prove all three are bit-identical. `calm_frac` is passed to the Stage 2 sampler (§4.6).
- `observation_space = Box(-1, 1, (OBS_DIM,), float32)`, `action_space = Discrete(8)`
- `action_masks() -> np.ndarray[bool, 8]` returns the current ego's mask.
- `reset(seed, options)` samples a scenario (`options={"scenario": Scenario}` overrides) and advances to the first decision.
- `step(a)` returns `(obs, reward, terminated=False, truncated, info)`. `truncated` is set when `tick·DT_S ≥ episode_s`. Then `obs` is a zero vector and the next mask is CONTINUE-only.
- `info` carries the `cost_totals` deltas for AI and twin and the action name. With `credit_info` (default) it also carries the §4.4 per-train credit data, all unscaled: `t_s` (episode seconds at this decision), `route` (ego route index), `imm_cost` (immediate cost of this action; 0 if not applied), `d_flow_global` ((ΔC_ai − ΔC_twin) of this step's ticks without immediate costs, so `reward == clip(−REWARD_SCALE·(imm_cost + d_flow_global), ±REWARD_CLIP)`) and `d_route` (float32[n_routes] scoped flow deltas). Before a lazy fork all deltas are 0.
- Episodes with no decision at all are skipped by resampling (cap 5 tries, then return a dummy CONTINUE-only step).

### 4.6 Training — GUIDANCE with CONTRACT outputs (`rl/train.py`)

**Algorithm and network**
- MaskablePPO with `MlpPolicy`, `net_arch=dict(pi=[256,256], vf=[256,256])` and `activation_fn=nn.Tanh`.
- Hyperparameters:

  | Parameter | Value |
  |---|---|
  | `n_steps` | `auto` per §4.10 (1088 for 14 workers; `--n-steps 1024 --batch-size 2048` reproduces the original table) |
  | `n_envs` | `auto` per §4.10 (14 on the M5 Pro) |
  | `batch_size` | `auto`: the exact divisor of the rollout closest to 2048 |
  | `n_epochs` | 5 |
  | `gamma` | 0.995 |
  | `gae_lambda` | 0.95 |
  | `clip_range` | 0.2 |
  | `ent_coef` | 0.01 → 0.001, linear |
  | `learning_rate` | 3e-4 → 5e-5, linear |
  | `max_grad_norm` | 0.5 |

- No `VecNormalize` on observations (obs are already normalized by `build_obs`).
- **Credit assignment** (`--credit`, WP5b): `per-train` (default) trains on the §4.4 per-train semi-MDP; `serial` is the WP5 baseline (ablation, bit-identical to it).

  | Setting | `per-train` (default) | `serial` |
  |---|---|---|
  | Transition | one train's decision → its next own decision (or episode end) | one global decision → the next decision of any train |
  | Discount | `--gamma-min 0.96` per sim-minute | `gamma` 0.995 per decision |
  | λ | 0.95 per own decision | 0.95 per global decision |
  | Reward | route-scoped twin delta (`--reward-scope route`, `--scope-neighbor-weight 0.35`) | env reward (citywide twin delta) |
  | Reward normalization | running std (Welford) of the per-train returns `G_k = R_k + Γ_k·G_k′`; R / std clipped to ±10 | `ReturnNormalizer` (`VecNormalize(norm_reward=True)` rule) |
  | Buffer | rebuilt each rollout with exactly the closed transitions; mini-batch `ceil(N / max(1, round(N/2048)))` | `n_envs·n_steps` rows, `batch_size` |
  | `--target-kl` | 0.02 | none |
  | `--calm-frac` | 0.12 | 0 |

  Both normalizers' state is saved in `train_state.json` (`reward_normalizer`; the per-train one has `"kind": "per_train"` and is only restored into a per-train run), next to the resolved `credit` settings. `--no-reward-norm` disables either.
- **Per-train rollout boundaries.** A transition whose train has not decided again yet, in a running episode, is *open*. It is carried into its worker's next rollout (the env state persists) and closed there; before the GAE its V is recomputed with the current critic, while its behavior `log_prob` is kept. The λ-recursion is truncated at an open transition, the way truncated GAE treats a rollout end. A transition still open after more than 3 rollouts is closed as terminal, and `--resume` drops the carry set. `num_timesteps` counts env steps collected. Logged: `rollout/closed`, `rollout/carried`, `rollout/mean_interval_s`, `rollout/R_mean`, `rollout/R_std`, `credit/scope_global_corr` (scoped vs. global R over the same intervals) and the usual action and mask rates.
- **Collection** (`rl/rollout.py`, `rl/ppo.py`): spawned `RolloutWorkers` each run the current policy in NumPy over 64-step chunks, handed out dynamically, with one barrier per rollout. SB3's per-step `SubprocVecEnv` loop managed only 15 % parallel efficiency, because step times are heavy-tailed. The MaskablePPO update and the checkpoint format are unchanged (`MaskablePPO.load` works), and the env remains `SubprocVecEnv(spawn)`-safe.
- GAE treats the `episode_s` horizon as terminal and does not bootstrap from the zero terminal observation. The objective is finite-horizon and the observation carries `time_in_episode_frac`. The env still returns `truncated=True`.

**Curriculum**

| | Stage 1 — trunk school | Stage 2 — citywide |
|---|---|---|
| Steps | default 3M | default 10M |
| Routes operated | one random trunk group per episode (Lexington 4/5/6/6X, 7 Av 1/2/3, 8 Av A/C/E, 6 Av B/D/F/FX/M, Broadway N/Q/R/W, QBL E/F/M/R, Flushing 7/7X, Canarsie L, Nassau J/Z/M, Crosstown G) | all routes |
| Disruptions | 1–2 on that trunk, plus random headway jitter (bunching) | 1–4 anywhere, all kinds; a `--calm-frac` share (per-train default 0.12) are calm anchors with none (jitter and domain randomization as usual), against over-intervention on mild days |
| Profile | random | all 4 profiles |
| Episode | 3600 s | 5400 s |
| Domain randomization | — | `demand_scale` U[0.8,1.3], `dwell_scale` U[0.85,1.25], `speed_scale` U[0.9,1.05], disruption start U[300,1500] s, duration U[600,2400] s or until end |

**Throughput target:** ≥ 2,000 env-steps/s aggregate on 14 workers, measured by `rl.bench_env`.

**Outputs**, under `--run-dir` (Colab: `/content/drive/MyDrive/subway-domino/runs/<name>`):
- `checkpoints/ckpt_<steps>.zip` every 250k steps, written atomically (tmp then rename) and keeping the last 5
- `latest.zip` and `best_model.zip` (best by validation eval)
- `train_state.json`: `{stage, steps_total, steps_stage, best_score, run_id}` (plus bookkeeping: `reward_normalizer`, `credit`, ...)
- `tb/`: TensorBoard logs, with scalars for reward, twin advantage, per-action rates, mask validity and the validation metrics

`--resume auto` loads `latest.zip` and `train_state.json` if present and continues with `reset_num_timesteps=False`, so a Colab disconnect loses at most 250k steps.

**Validation:** every 500k steps, 8 fixed validation seeds, `eval_scenario(VALIDATION_SEED_BASE + i)` with `VALIDATION_SEED_BASE = 2_000_000`. These are citywide meltdowns kept separate from eval, so model selection mirrors §4.7 even during Stage 1. The score is the mean twin-relative cost reduction.

### 4.7 Evaluation — CONTRACT (`rl/evaluate.py`)

- Run `eval_scenario(EVAL_SEED_BASE + i)` for i < 50, twice: Normal (all CONTINUE) and AI (`load_policy`). The scenario is the same for both and each run lasts the full `episode_s`.
- Per seed, record:
  - the time-averaged `avg_wait_min`
  - overcrowded platform-minutes
  - tunnel-stuck train-minutes
  - `riders_served`
  - the cost totals
  - action counts
- Outputs:
  - `eval_report.json`: per-seed rows plus aggregates (mean, 95 % bootstrap CI, AI-vs-Normal % change, seed win rate)
  - `eval_report.md`: a human-readable table
  - `eval_per_seed.csv`
- Exit code 0 always. A `--require-win` flag returns 1 unless the AI beats Normal on mean total cost **and** on at least 3 of the 4 UI metrics.

### 4.8 Acceptance bar for shipping a model

The AI must beat Normal on mean total cost across the 50 eval seeds, with a seed win rate ≥ 70 %. It must also reduce **tunnel-stuck train-minutes** by ≥ 30 %, and it must **remove ≥ 20 % of the disruption-induced excess avg wait**. The excess is measured as Normal minus a calm counterfactual, i.e. the same scenario without its disruptions under Normal Schedule. It is a ratio of sums over the seeds, reported with a 95 % seed-bootstrap CI. The 20 % threshold was confirmed with the user on 2026-11-22. It equals what a rule-based incident dispatcher removes on the same 50 seeds: 20 %, CI 12–28 %. That dispatcher is an evaluation-only benchmark, never shipped. The best RL model removes 25 %. Otherwise iterate: rewards, masks, features, or train longer.

*Changed with the user on 2026-11-22.* This replaces "avg wait by ≥ 10 %". Disruptions add only ~21 % to citywide avg wait on the eval seeds (4.92 vs 3.90 min), and less than 10 % on 20 of the 50 seeds, so a citywide 10 % cut was unreachable there for any dispatcher. The citywide % change is still reported for information.

*Shipping exception, 2026-11-22.* The product owner chose to ship the per-train / citywide-reward model (`backend/models/nyc_subway_rcc_ppo.onnx`) while the bar is not fully met. It passes cost, win rate (86 %) and excess-wait removal (24 %), but tunnel-stuck falls only 27.4 % against the 30 % target. The model card's `ship_decision` records this.

## 5. Backend server (WP4)

### 5.1 Structure & lifecycle

- **Startup.** `app/main.py` creates the FastAPI app. Its lifespan loads `Graph` once (read-only arrays shared by all sessions) and `OnnxPolicy` once (`intra_op_num_threads=1`, `inter_op_num_threads=1`, sequential execution mode).
- **Model failure.** If the model fails to load, log it, set `model_loaded = False`, and keep serving Normal mode. **AI mode is then unavailable. There is never a heuristic fallback.**
- **HTTP routes:**
  - `GET /health` → exactly `{"status":"ok","model_loaded":<bool>}`
  - `GET /stats` → sessions, governor load, uptime, graph_version
  - `GET /network_geo.json` → the same file as the frontend's copy (fallback)
- **CORS:** `CORSMiddleware(allow_origins=ALLOWED_ORIGINS)`. `ALLOWED_ORIGINS` is a comma-separated env var, default `https://kenmar.dev,http://localhost:3000`. The **WebSocket `Origin` header is checked manually** against the same list; a mismatch closes with code 1008. A missing Origin is allowed only when `ALLOW_NO_ORIGIN=1` (tests and smoke).
- **WebSocket** `GET /ws`. On connect:
  - if `active_sessions ≥ MAX_SESSIONS` (env, default **40**): accept, send `{"type":"at_capacity","message":"Subway Domino is at capacity right now — please try again in a minute."}`, close with code 1013;
  - otherwise create a `Session`.

### 5.2 Session loop — CONTRACT constants

| Constant | Value |
|---|---|
| `FRAME_HZ` | 4 |
| `METRICS_HZ` | 1 |
| `MAX_SESSIONS` | 40 |
| `IDLE_TIMEOUT_S` | 300 |
| `DETACH_GRACE_S` | 90 |
| `CPU_BUDGET` | 0.70 |

- **Per session:** one asyncio task. Every 1/`FRAME_HZ` s it computes the ticks owed: `speed_sim_per_s / FRAME_HZ / DT_S`, kept in a fractional accumulator and capped at 8 ticks per frame.
- **Each tick:**
  - **AI mode:** take the `pending_decisions()` batch, call `OnnxPolicy.act` on the whole batch, then `apply_actions` and `step(1)`.
  - **Normal mode:** `step(1)` only.
  - **Twin:** when it exists, it gets `twin.step(1)`; its decisions resolve to CONTINUE.
- **Twin lifecycle:**
  - created via `sim.copy()` when the session switches to AI;
  - user disruption changes are mirrored to it;
  - dropped on the switch back to Normal, on reset, or on a profile change.
- **Messages:** one binary frame after the ticks of each frame cycle. A `metrics` JSON at `METRICS_HZ`, plus `events` and `disruptions` JSON when they change.
- **Backpressure:** if a send is still pending, skip the frame. Frames are idempotent keyframes.
- **CPU governor:** a manager-level EWMA of CPU seconds per wall second across sessions. When it exceeds `CPU_BUDGET`, scale all sessions' tick budgets by `CPU_BUDGET/load`, so every session slows equally. The effective speed factor goes out in `metrics.effective_speed`.
- **Idle:** the timer resets on any client message except `ping`. At `IDLE_TIMEOUT_S`, send `{"type":"idle_timeout"}` and close with code 1000.
- **Resume:** on disconnect, the session is kept paused for `DETACH_GRACE_S` under its `resume_token`; detached sessions do not count toward `MAX_SESSIONS`. A `hello` with a valid token reattaches to the exact state. Otherwise the client's `restore` payload re-creates the settings and disruptions.

- The web client offers only blockage kinds (`full_station_closure`, `local_block`, `express_block`) and always sends `"duration_s": null`, so every disruption it starts lasts until the user clears it.
- `preset` serves the preset's disruptions as blockages too (`app.session.as_blockages`): each gets `duration_s = None` (`end_t: null`), and a `signal_delay` becomes a `local_block` on the same target. `network.json`, its `graph_version` and `sim.preset_scenario` are untouched, so WP2's calibration still uses the timed presets.

### 5.4 Callouts — CONTRACT behavior (`app/callouts.py`)

- Every applied non-CONTINUE AI action yields at most one callout. Plain-English text is built from `ActionEvent` (route bullet, station names, rider counts, the blocked-ahead description).
- The text is **factual about the situation and the action**, never a claimed inner reasoning. Example: "Holding a 4 at 59 St with doors open — the track ahead at Grand Central is blocked, so 840 riders wait on a platform instead of a stalled tunnel."
- Rate limit: ≤ 1 callout per 1.5 s real time per session. Excess actions are aggregated as "+3 more dispatch actions".
- There is one template family per action, each with variants for the main `detail` cases.

**Rendering — CONTRACT behavior:**
- **Canvas 2D:** device-pixel-ratio aware, pan (drag) and zoom (wheel/pinch) about the cursor. Zoom runs from full NYC (≈ 60 m/px) to dense Midtown (≈ 1.5 m/px).
- **Line widths, markers and labels are in screen pixels**, so the map is crisp at every zoom.
- **Segments** are drawn as bundles of route-color strokes (one per distinct route color using the segment) offset side by side. River-crossing segments get a subtle dashed casing.
- **Labels** are shown by `label_rank` with zoom tiers and collision avoidance.
- **Station circles** are sized by zoom. Crowding is shown as a fill ramp (calm → amber → red) from `station_crowd`, with a pulse when it reaches ≥ 80. Closed stations show a black X.
- **Trains** are drawn as small rounded capsules in route color, oriented along the track. At high zoom they carry the route letter. Their status bits are shown as icons/halos: tunnel-stuck red halo, held amber ring, short-turning ↺, gap train ✚, rerouted dashed outline.
- **Positions** follow the §2.7 positioning rule. They are interpolated between the last two frames, matching trains by `train_id` and route: if a train's edge is unchanged, lerp `frac`. If the edge changed, move along the cheapest chain of continuing edges (each edge's to-station == the next one's from-station), at most 6 edges past the old one. The search prefers edges the train's route uses, penalises crossovers, turnbacks and reversals, and caches paths per (prev, next, route). Real discontinuities are cross-faded rather than slid: a new trip in a reused slot (route changed, or `frac` ran backwards), no path, or a path longer than 1.25 · V_MAX_CAP · Δclock + 150 m. Speed may be eased across frame boundaries if positions at frame times stay exact (WP3b). Rendering runs at 60 fps with `requestAnimationFrame`, and the dynamic layer only is redrawn each frame.
- **Disruptions** are drawn on their target: red hatched segment for a block (local/express track side), black ring for a closure (amber dashed for a signal delay, which the UI no longer starts). Each shows a status chip with no countdown: "CLOSED" / "BLOCKED" when zoomed out, "LOCAL BLOCKED" / "EXPRESS BLOCKED" closer in, plus "since 8:12 AM" at street zoom.
- **Interlockings** (small diamonds) and yards (small squares) appear from mid zoom.

**UX flow (CONTRACT):**
1. **Load.** The static map paints from the geo file before the socket connects. A skeleton shows until then, and trains animate as soon as `welcome` and the first frame arrive.
2. **Presets.** A visible PresetBar shows 3 presets prominently plus "More…". Clicking one recenters the camera on the preset's `focus` and starts the meltdown.
3. **AI toggle.** The big ModeToggle "Normal Schedule | AI Dispatcher" pulses after a disruption starts.
4. **AI mode.** Switching to AI shows the twin comparison in MetricsHUD (WP3b, 2026-11-22). Every value comes from live and twin metrics only.
   - It leads with a **since-takeover** comparison: rider-minutes waited, AI vs Normal, plus a one-line verdict ("AI ahead on k of 4"). The verdict has a small hysteresis so it does not flip at the edge.
   - Per-metric "right now" deltas are green or red. A delta stays neutral grey inside a dead band (|Δ| < 3 % or ±1 unit), so noise does not read as a result.
   - Each sparkline draws the twin as a solid grey second line and shades the disruption window. CalloutLayer shows toasts and ActivityFeed lists all actions.
5. **Any target.** Clicking a station, segment, interlocking or river crossing opens a DisruptionPopover listing only the blockage kinds valid for that target (closure, local block, express block; no signal problems). There is no duration: every blockage lasts until the user clears it (WP3d, 2026-11-22). Search (by station name and route) flies the camera there.
   - On a target that is already blocked, the popover leads with each active block ("Blocked since 8:12 AM") and a **Restore service** button; adding another block there is one click away.
   - The "Break the city" menu lists the active blockages ("since …", locate, **Restore**) plus **Clear all**.
   - When the user clears a block (one or all), a green "Service restored" notice says what reopened ("14 St–Union Sq reopened", "…: local track clear again", or "Service restored at N places"). Ends caused by a reset, preset or profile change stay silent. On phones this notice briefly takes the place of the AI callout.
   - Preset titles that the data words as a timed signal problem get a frontend copy override by id (`times-sq-signals` → "Tracks blocked at Times Sq–42 St").
6. **InfoModal:**
   - datasets with links (`fgm6-ccue`, `5f5g-n3cz`, `5wq4-mkjj`);
   - how the sim works;
   - the reward terms;
   - the 8 actions and their masking rules (§4.2 in plain English);
   - the live action breakdown from `metrics.actions`;
   - "AI unavailable" notes when `ai_available=false` (the toggle is disabled with a tooltip).
7. **Connection lifecycle:**
   - **Hidden tab:** after > 60 s hidden (`visibilitychange`), close the socket.
   - **Return:** reconnect with `hello{resume_token, restore}` and show a ConnectionBanner briefly.
   - **At capacity:** show a friendly banner and retry after 30–60 s with jitter.
   - **Idle timeout:** show "Paused — click to resume".
8. **First-use goal.** The first meltdown can be triggered and the AI toggled within 10 s, without instructions. Onboarding is a single dismissible coach-mark pointing at the PresetBar, then at the toggle.

## 10. Risks & mitigations

| Risk | Mitigation |
|---|---|
| **The AI doesn't beat the baseline** | twin-difference reward; need-clause masks so decisions are sparse and meaningful; tunnel ≫ hold cost asymmetry; Stage 1 trunk school; acceptance bar §4.8 gates shipping; iterate coefficients via `constants.py` |
| **Topology inference errors** (express/crossover/turnback) | overtake evidence plus the curated overlay; invariant tests; `build_manifest.json` counts; visual check in the frontend at Midtown zoom |
| **Sim too slow for 40 sessions** | vectorized kernel, §3.7 perf tests, CPU governor, twin only in AI mode, ticks capped per frame |
| **Bandwidth** | binary SoA frames at 4 Hz, permessage-deflate, skip-on-backpressure |
| **Colab timeouts** | atomic checkpoints every 250k steps on Drive, `--resume auto` |
| **ONNX drift** | single exported actor with metadata (`graph_version`, `constants_hash`); the server logs a warning on mismatch; a parity test |
| **basePath bugs** | the `asset()` helper, a build check, and testing `/subway` locally |
